# 工程化说明

> 目的：让「漏导入、未使用变量、类型错误、调试残留」在提交前/推送前被自动拦住。
> 本项目已经因为「漏导入 showToast」栽过 3 次，这套配置就是为了终结它。

## 一、工具分工

| 环节 | 工具 | 命令 | 抓什么 |
|---|---|---|---|
| 写代码时 | ESLint（编辑器插件） | — | 实时红波浪线 |
| 提交前（钩子） | husky + lint-staged | `npx lint-staged` | **只查本次改动的文件**：未使用变量、漏导入、`console.log` 残留、格式 |
| 推送前（钩子） | husky + vue-tsc | `npm run typecheck` | **全量类型检查**：`TS2322`、可能 undefined、模板里的类型错 |
| 推送后（云端） | GitHub Actions | `.github/workflows/ci.yml` | lint + typecheck + **build**（构建期才暴露的错误） |

**为什么分层**：pre-commit 只跑改动的文件（秒级），否则每次提交要等 40 秒，人就会开始用 `--no-verify` 绕过；全量类型检查放到 pre-push；CI 兜底是因为钩子可以被绕过。

## 二、常用命令

```bash
npm run lint        # 全量检查
npm run lint:fix    # 全量自动修复（缩进、引号、括号等格式类）
npm run typecheck   # 类型检查（约 30-60 秒）
npm run build       # 生产构建
```

## 三、报错了怎么办

### 1. ESLint 报 `'xxx' is defined but never used`（当前最常见）

```
app/pages/cart.vue
  2:56  error  'Icon' is defined but never used  @typescript-eslint/no-unused-vars
```

三种情况，对应三种修法：

- **真的没用了** → 从 import 里删掉
- **是功能没用上** → 说明有 bug（本项目就发生过：`onConfirm` 定义了但从没绑定到 `<Search @search>`，导致回车搜索形同虚设）
- **确实要保留** → 变量名加下划线前缀 `_foo`（规则允许）

### 2. ESLint 报格式类（`@stylistic/*`）

直接 `npm run lint:fix`，一条命令修完，不需要手工调。

### 3. TS 报 `Object is possibly 'undefined'`

项目开了 `noUncheckedIndexedAccess`：任何 `arr[i]`、`obj[key]` 的结果都带 `undefined`。三种修法（按推荐顺序）：

```ts
// ✅ 1. 先解构再判空（类型自然收窄）
const [first, second] = list
if (!first) return ''

// ✅ 2. 抽取值函数，显式兜底/抛错
function specSetOf(id: number) {
  const set = SPEC_SETS[id] ?? SPEC_SETS[1]
  if (!set) throw new Error(`未配置规格集：${id}`)
  return set
}

// ⚠️ 3. 非空断言 list[0]!（仅当逻辑上绝不可能为空，且要有注释说明）
```

### 4. 想跳过钩子

**不要**。`git commit --no-verify` 会让 CI 报红，问题还是你的。唯一合理的场景是紧急修复 CI 配置本身。

## 四、配置在哪

| 文件 | 作用 |
|---|---|
| `eslint.config.mjs` | ESLint 规则（基于 `@nuxt/eslint` 生成的 flat config） |
| `nuxt.config.ts` → `eslint.config.stylistic` | 格式规则交给 `@stylistic`，不额外引 Prettier（两个格式化器会打架） |
| `.husky/pre-commit` | 提交前跑 `npx lint-staged` |
| `.husky/pre-push` | 推送前跑 `npm run typecheck` |
| `package.json` → `lint-staged` | 钩子只看 `*.{js,mjs,ts,vue}` 的暂存文件 |
| `.github/workflows/ci.yml` | 推送/PR 到 main、dev 时云端跑 lint + typecheck + build |
| `.editorconfig` | 编辑器层兜底：utf-8 / 2 空格 / LF / 文件末尾换行 |
